# Заповедный компас

Мини-приложение Telegram/MAX: карта природоохранных территорий, проверка точки, сообщение в бот проекта и спутниковые термоточки.

https://krackenhell.github.io/zapovedny-kompas/

## Регионы

Подключены юг Тюменской области (без ХМАО/ЯНАО), Москва (включая Новую Москву), Московская область. Каталог на 25.10.2026: **25 уникальных территорий**, из них 9 в Тюменской области, 6 в Москве и 11 в Подмосковье. Лосиный остров пересекает Москву и область и доступен в обоих фильтрах. Каталог неполный.

- Исходные 4 территории Ишимского округа и их правила сохранены.
- Новые контуры взяты из OpenStreetMap, проверены на корректность геометрии и пересечение регионов. Незначительные пограничные наложения менее 0,1% площади исключены из региональной принадлежности.
- Границы справочные, не юридические. Режим новых территорий не проверен: приложение не выдумывает запреты и не показывает телефон Ишимской инспекции для Москвы.
- Совпадения с деревнями, улицами и обычными парками отсеяны. Затюменский лесопарк включён по отдельно подтверждённому статусу ООПТ; его OSM-контур не выдаётся за кадастровую границу.
- При отсутствии совпадения приложение сообщает лишь об отсутствии территории в загруженном каталоге.

## Пожары

GitHub Actions запрашивает NASA FIRMS каждый час (фактический запуск может задерживаться). Источники: VIIRS NOAA-20 и NOAA-21. Показываются все термоточки в административных границах выбранного региона за скользящие 48 часов, с фильтром «Только рядом с ООПТ» (до 5 км от загруженных контуров).

На GitHub Pages приложение читает последний файл снимка из публичной ветки main через raw.githubusercontent.com; локальный data/fires.json используется как резерв. Поэтому обновления данных не зависят от пересборки страницы.

Ключ — исключительно в GitHub Actions Secret FIRMS_MAP_KEY. В публичных файлах его нет. Три календарных дня API запрашиваются для корректной выборки последних 48 часов. Дубли одного спутника удаляются; наблюдения разных спутников сохраняются.

Сбой региона не останавливает остальные: предыдущий снимок сохраняется с ошибкой обновления. Интерфейс явно отмечает сбой или давность более трёх часов и не подменяет недоступность данных нулём пожаров. Успешная проверка обновляет время даже при неизменных данных.

Термоточка — спутниковый сигнал, не подтверждённый пожар. Отсутствие сигналов не гарантирует отсутствие огня.

## Бот и сообщения

Расширена карта мини-приложения. Существующий бот и его подписка пока обслуживают Ишимский округ. Приём сообщений через Telegram/MAX сохранён; автоматическая передача региональным ведомствам не подключена. Интерфейс сообщает об этом до отправки.

## Файлы

- index.html — приложение, выбор региона, поиск и карта.
- pitch.html — исходный питч проекта, сохранён.
- data/zones.json — каталог и полигоны регионов.
- data/sources.json — происхождение каждого контура.
- data/fires.json — региональные снимки спутниковых данных.
- tools/update_fires.py — обновление без сторонних Python-библиотек.
- tools/build_regions.py — сборка из проверенных выгрузок Nominatim; требует shapely==2.1.2. При повторном экспорте старым tools/build_miniapp_data.py из бота расширенный каталог будет заменён, поэтому старый экспорт нельзя применять поверх этой версии.

## Время наблюдений

По умолчанию показаны съёмки за последние 6 часов; историю можно расширить до 12, 24 или 48 часов. Наблюдения старше 6 часов выделены как история и не обозначают действующий пожар. Карточка показывает точное время съёмки с часовым поясом, координаты и время первого получения сервисом для новых записей. Для старых записей время получения неизвестно и не восстанавливается вымышленно.

Возраст съёмки не равен задержке доставки. NASA NRT обычно публикует данные в пределах 3 часов после пролёта; промежуток между пролётами и доступность наблюдений не позволяют гарантировать обнаружение за 3–5 часов с момента возникновения огня. Частота нашего опроса (раз в час) не меняет частоту съёмок спутником. Источник: https://firms.modaps.eosdis.nasa.gov/.

Фактические запуски GitHub Actions могут существенно отставать от cron. Это не канал с гарантированным временем оповещения. Для предсказуемого опроса потребуется постоянно работающий сервер с контролем задержек; даже он не меняет пролёты и публикацию исходных спутниковых данных.
